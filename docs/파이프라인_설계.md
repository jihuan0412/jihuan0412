# 영화·드라마 비화 쇼츠 — 파이프라인 설계

작성일: 2026-09-03
기준 문서: `docs/기획서.md`
목적: 다른 세션에서 이 문서만 읽고 바로 실행에 들어갈 수 있는 수준의 공정 정의

---

## 0. 설계 원칙

1. **비용이 발생하는 단계 앞에는 반드시 사람 게이트를 둔다.**
   렌더링·라이선스 구매·발행이 비용 지점이다. 그 앞에서 걸러야 한다.
2. **되돌릴 수 없는 리스크를 앞단에서 죽인다.**
   저작권 사고는 영상을 내리면 끝나지만, 허위사실·명예훼손은 회복되지 않는다.
   따라서 사실 검증은 대본보다 **앞**에 온다.
3. **자동화는 수집과 렌더에만 투자한다.**
   대본은 채널의 유일한 차별점이므로 자동화 대상이 아니다.
4. **모든 산출물은 파일로 남긴다.**
   중간 결과가 대화 속에만 있으면 다음 세션이 이어받지 못한다.

---

## 1. 공정 개요

```
S0 소재 발굴 ──[게이트 1: 신선도]──> S1 사실 검증 ──[게이트 2: 사실]──>
S2 대본 ──[게이트 3: 대본 확정]──> S3 소재 조달 ──> S4 나레이션·자막 ──>
S5 렌더 ──> S6 발행 ──> S7 측정 ──(피드백)──> S0
```

게이트는 3개. 각 게이트는 통과/보류/폐기 세 가지 판정만 낸다.

---

## 2. 단계별 정의

### S0. 소재 발굴 (Discovery)

- **입력**: 작품 후보 (신작 개봉·공개 캘린더 / 구작 풀)
- **작업**: 작품 1편당 비화 후보를 여러 건 수집한다. 출처 URL을 반드시 함께 기록한다.
- **출력**: `후보.json`
  ```
  {
    "작품": "", "연도": "", "구분": "신작|구작",
    "각도": "원작자|제작계기|촬영비화|캐스팅|작품연결",
    "한줄": "",
    "출처": ["url", ...],
    "신선도": "상|중|하",
    "화면조달": "예고편|스틸컷|공식행사|인터뷰클립|라이선스구매|퍼블릭도메인"
  }
  ```
- **자동화**: 검색·수집은 자동화 가능. 신선도 판정은 사람.
- **주의**: `화면조달` 필드를 이 단계에서 채운다. 대본을 다 쓰고 나서
  "쓸 화면이 없다"를 발견하면 그 시점까지의 작업이 전부 매몰비용이 된다.

#### 게이트 1 — 신선도
- 나무위키 본문 상단, 위키백과, 대형 채널(구독 10만+)에 이미 나와 있으면 **폐기**
- 기사 검색 결과 1페이지에 바로 뜨면 **폐기**
- 통과 기준: "이 사실을 알려면 최소 2~3단계를 파고들어야 한다"

---

### S1. 사실 검증 (Verification)

> 기획서에 없던 단계. 신설.

- **입력**: 게이트 1 통과 후보 1건
- **작업**: 주장 단위로 쪼개서 출처를 매핑한다.
  - 1차 소스(당사자 인터뷰, 공식 기록, 제작기·코멘터리)가 있으면 최상
  - 2차 소스(기사)는 **서로 독립적인** 매체 2개 이상. 같은 보도자료를 받아쓴 기사들은 1개로 센다.
- **출력**: `검증.md` — 주장별로 [확인 / 단일출처 / 미확인] 표시 + 출처 링크
- **자동화**: 불가. 사람이 판단한다.

#### 게이트 2 — 사실
- 인물에 대한 **부정적 서술**은 1차 소스가 없으면 **무조건 폐기**. 예외 없음.
- 독립 출처 2개 미만 → 폐기, 또는 "~라고 알려져 있다" 화법으로 강등 후 통과
- 소문·팬덤 추측 기원 → 폐기
- **이 게이트를 통과하지 못한 소재는 아무리 조회수가 나올 것 같아도 버린다.**
  한국은 사실적시 명예훼손도 처벌 대상이며, 채널 하나가 아니라 사업 전체가 걸린다.

---

### S2. 대본 (Script)

- **입력**: 검증 통과 소재 1건
- **출력**: `대본_ko.md` — 블록 분리, 블록별 목표 초수, 나레이션 + 화면 지시 병기
  - `0~2초` 훅 — 모르는 사실을 먼저 던진다
  - `2~10초` 작품 특정 — 예고편 클립으로 어떤 작품인지 즉시 인지시킨다
  - `10~45초` 본문
  - `45~60초` 마무리 + 다음 편 유도
- **분량 규칙**: 할 말이 끝나면 끊는다. 60초를 채우려고 늘리지 않는다.
- **자동화**: 하지 않는다. 대본 품질이 채널의 유일한 해자다.

#### 게이트 3 — 대본 확정
- 사람이 소리 내어 읽고 승인한다.
- **이 게이트 통과 전에는 TTS·이미지 구매·렌더를 절대 시작하지 않는다.**
  여기부터가 실제 돈이 나가는 구간이다.

---

### S3. 소재 조달 (Asset)

- **입력**: 확정 대본의 화면 지시
- **작업**: 예고편 사용 구간 특정 / 배급사 스틸컷 / 공식 행사·인터뷰 클립 /
  라이선스 이미지 구매 / 퍼블릭 도메인 자료
- **출력**: `assets/` + `출처대장.csv`
  ```
  파일명, 종류, 출처URL, 권리자, 라이선스근거, 취득일, 비용
  ```
- **출처대장은 선택이 아니라 필수다.** 두 가지 역할을 한다.
  1. 신고가 들어왔을 때의 방어 문서
  2. 애초에 못 쓸 소재를 대장에 못 적는 방식으로 걸러내는 필터
- **금지**: 본편 영상 캡처, 무음 구간 잘라내기 등 Content ID 회피 편집

---

### S4. 나레이션 · 자막

- 한국어 TTS 생성 → 타임코드 확정 → 번인 자막 생성
- 자막은 화면에 태워 넣는다(번인). 자막 애니메이션 적용.
- **영어 채널(2단계)**: 번역이 아니라 영어권 화법으로 **재작성**한다.
  번역기 티가 나면 현지화 버전이 아니라 재사용 콘텐츠로 읽힌다.

---

### S5. 렌더

- 9:16 / 1080x1920
- 이미지·클립 시퀀스는 언어 공통. 오디오·자막 레이어만 교체 후 재렌더링.
- **자동화 투자 대상.** 여기는 반복 작업이며 품질 차별점이 아니다.

---

### S6. 발행

- 제목·설명·태그를 언어권별로 완전 현지화 (기계 번역 금지)
- **출력**: `발행기록.json` — 발행일시, URL, 제목, 사용 각도, 작품 구분(신작/구작)

---

### S7. 측정 → 피드백

- **주기**: 2주
- **지표**: 조회수가 아니라 시청 지속률, 그리고 총 시청 시간
- **피드백**: 각도별·작품구분별 성과를 집계해 S0의 후보 우선순위를 갱신한다
- **폐기 기준(kill criteria)**: 아래 4절 참조

## 4. 창업 관점 — 기획서에서 빠진 것

### 4.1 채널은 1개로 시작한다

기획서는 채널 3개 안을 "초기 노출 분산, 데이터 3분할로 판단 불가"를 이유로 폐기했다.
같은 논리가 채널 2개에도 그대로 적용된다.

- 초기 10편의 목적은 **어떤 각도가 먹히는지 실험**이다
- 검증되지 않은 각도로 영어 대본까지 재작성하면 실험 비용만 늘고 데이터는 반으로 갈린다
- **결정: 1단계(1~10편)는 한국어 채널 단독. 각도 검증 후 영어 채널을 붙인다.**
- 영어 채널을 위한 준비(에셋·시퀀스 공용화)는 처음부터 해둔다. 붙이는 시점만 미룬다.

### 4.2 각도 우선순위와 원가의 역방향 문제

| 각도 | 화면 조달 | 편당 원가 |
|---|---|---|
| 원작자·작가 이야기 | 라이선스 이미지 필수 (예고편에 화면 없음) | 높음 |
| 제작 계기 | 예고편 + 감독 인터뷰 클립 | 중간 |
| 촬영 비화 | 예고편 + 메이킹·공식 클립 | 낮음 |
| 캐스팅 비화 | 배우 사진 → 라이선스 필요 | 높음 |
| 작품 간 비교·연결 | 예고편 2편 조합 | 가장 낮음 |

기획서의 우선순위 1위가 원가 최고다.
**초기 10편은 원가가 낮은 각도(촬영 비화 / 작품 간 연결)를 섞어서 시작한다.**
원가 높은 각도는 어떤 각도가 먹히는지 확인된 뒤에 투입한다.

### 4.3 런웨이

시작 전에 아래 숫자를 확정해야 한다. 지금은 비어 있다.

- 편당 평균 라이선스 이미지 비용
- 편당 사람 투입 시간 (특히 S0·S1이 전체의 대부분을 차지할 것)
- 유튜브 수익화 조건 도달까지 필요한 편수 추정 → **현행 조건 확인 필요**
- 위 셋을 곱한 값 = 수익 0원 구간에 태울 총비용과 기간

이 계산 없이 시작하면 언제 접어야 하는지도 판단할 수 없다.

### 4.4 폐기 기준 (kill criteria)

2주 단위 평가에 판정 규칙을 붙인다. (수치는 첫 2주 데이터로 보정한다)

- 2주 연속 지속률 목표 미달 → **각도 교체**
- 각도를 두 번 바꿔도 미달 (누적 6주) → **컨셉 재검토**
- 저작권 신고 또는 사실관계 정정 요구 1건 발생 → **전체 발행 중단, 파이프라인 감사**

## 5. 자동화 우선순위

| 순위 | 대상 | 이유 |
|---|---|---|
| 1 | S5 렌더 | 반복 작업, 품질 차별점 아님, 언어 확장 시 효과 배가 |
| 2 | S0 수집 | 사람 시간을 가장 많이 먹는 구간. 단 판정은 사람이 유지 |
| 3 | S6 발행 | 편수가 쌓이면 유의미 |
| — | S1 검증 | **자동화 금지.** 판단 실패의 대가가 가장 크다 |
| — | S2 대본 | **자동화 금지.** 채널의 유일한 해자 |

## 6. 미결정 사항

기획서에서 이월된 항목:

- 훅 문형 템플릿 (도입부 2초 패턴 3~5종)
- 초기 10편 후보 리스트
- 나레이션 TTS 선정 (한국어 우선. 영어는 2단계에서)
- 리서치 소스 화이트리스트
- 라이선스 이미지 조달 예산 및 사용 기준
- 채널명 및 브랜딩
- 업로드 케이던스
- 소스 수집 자동화 범위

이번 설계에서 추가된 항목:

- 유튜브 수익화 조건 현행 기준 확인 (4.3의 런웨이 계산 전제)
- 지속률 목표 수치 확정 (4.4의 폐기 기준 전제 — 첫 2주 데이터 필요)
- 각도별 표준 화면 구성 정의 (2.S0의 `화면조달` 필드를 채우기 위한 기준표)

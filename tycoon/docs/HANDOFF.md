## 2. 확정된 결정
- 1단계 목표는 **60분에 구독자 1만** — 사용자 결정 (설계서의 30분/60분 불일치 해소).
- 현금 결제는 **실물 성격 아이템만**(컴퓨터 부품·장비·작업 공간·강의 묶음). 구독자·게임머니·수익 배율은 팔지 않는다. 결제 상품은 게임머니로도 살 수 있는 것만 — 사용자가 직접 바로잡은 방향. 지금은 모의 결제.
- 그래픽은 **Three.js 로우폴리 3D 미니어처 방**(비스듬히 내려다보는 시점). 사용자가 2D 픽셀을 "옛날 그래픽"이라 거절함. 2D(`scene.js`)는 WebGL 불가 기기 대체용으로만 둔다.
- 화면 구성: **방이 전체 화면**, 위에 정보·진행 카드, 아래 메뉴(제작·AI·팀·집·꾸미기·투자·미니홈·채널·상점), 누르면 아래에서 창이 올라옴.
- 시작은 지역(도시·농촌·바닷가·산속) → 집 → 장르·채널 이름·특성 → 시작 세트 — 사용자 요청.
- 음악은 **게임이 코드로 합성하는 작곡기(`music.js`)**를 쓴다. 저작권 위험이 없음. 플레이어 음악 파일 업로드는 넣지 않는다(법적 위험). Suno는 공식 공개 API가 없어 연결 불가(2026-07 초대제 파트너 프로그램만) — 사용자가 Suno에서 만든 유료 요금제 곡을 mp3로 주면 대표곡으로 넣는 방식만 가능.
- 미니홈·광장(싸이월드 느낌)은 아티팩트 공유 저장소(db+user 기능)로 **공유받은 사람끼리만** 동작하는 시제품. 일반 출시엔 별도 서버 필요.
- 설계 변경이 코드에 먼저 들어가 있다. 설계서 v0.3으로 옮기는 것은 사용자 확인 후 진행.

## 5. 버린 접근법
- 2D 코드 픽셀 그림 → 사용자가 그래픽이 낡았다고 거절. 3D로 교체.
- 방이 화면 위쪽 1/3만 차지하는 배치 → "게임 창 같지 않다"는 지적. 전체 화면으로.
- 설계서 조회수 식 `S^0.8` → 구독자 0이면 조회수 0. `(2000 + 20×S)^0.7`로 교체. 지수 0.8 이상은 후반 폭주.
- 장르별 조회수 계수 차이를 크게 둠 → 먹방 60분 21만으로 폭주. 차이를 작게.
- 후반 무제한 생산 → 수십억 구독자. 시청자 피로도·큰 채널 전환율 감소로 막음.

## 6. 참고
- 파일: `tycoon/engine.js`(규칙·데이터 표), `index.html`(화면), `scene3d.js`(3D), `decor.js`(꾸미기 모델), `music.js`(작곡기), `community.js`(공유 저장소), `homeui.js`(꾸미기·미니홈 화면), `build.js`(한 파일 빌드), `README.md`(기능·설계서 대비 변경점).
- 확인 명령: `node tycoon/sim/simulate.js 8` (밸런스), Playwright 헤드리스 크로미움은 `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader` 인자로 3D 확인.
- 아티팩트 공유 저장소 규칙: homes(본인만 씀)·comments·guestbook·visits(누구나 씀), user 기능 profile 범위. 이미 선언됨.
- 사용자 선호: 부드럽고 친절한 말투로(사용자 요청), 판단을 먼저 말하고 근거는 뒤에, 완충어 금지, 선택지 나열 대신 추천, 존댓말, 계획 결함은 먼저 지적, 커밋 메시지·결과물에 모델명 쓰지 않음.

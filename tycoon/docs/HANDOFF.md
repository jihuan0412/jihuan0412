# 세션 인수인계: 유튜브 채널 운영 타이쿤 → 생활 시뮬레이션으로 방향 전환
> 작성: 2026-11-02 · 이어서 진행할 작업: 새 틀 1단계 구현 (시간 속도·하루 흐름·오늘 할 일·메뉴 정리·책상=유튜브 일·성별/외모·옷장·신발장)

## 2. 확정된 결정
- **방향 전환**: 유튜브는 돈을 버는 수단이고, 게임의 몸통은 생활이다. 사용자 피드백 근거:
  - 무엇을 하는지 모르겠다.
  - 여기저기 누르게 되어 산만하다.
  - 틀이 없다.
  - 진짜 생활처럼 하고 싶다. 신발장·옷장을 열어 고르고, 동네를 걷다 갈림길에서 공원이나 가게로 가고, 성별도 고르고 싶다.
- **하루 = 실제 약 5분** (아침·낮·저녁·밤, 각 1분 남짓. 밤에 자면 다음 날).
  - 지금은 하루가 10초라 옷을 고르는 의미가 없기 때문이다.
  - 이에 따라 목표를 **"60분에 구독자 1만"에서 "60분(약 12일)에 구독자 1천~2천, 길게 키우기"로 바꾼다**. 예전 목표는 폐기한다.
- **영상 작업**: 직접 작업은 **책상에 앉아 있는 동안만** 진행된다. **AI·직원은 내가 생활하는 동안에도** 진행된다. "AI는 돈 버는 수단, 나는 생활" 구조를 화면에서도 느끼게 하려는 것이다.
- **방 안 물건이 곧 메뉴**: 책상=유튜브 일(제작·AI·직원·채널을 한곳에), 옷장=옷, 신발장=신발, 냉장고=먹기, 침대=잠, 문=외출. 아래 메뉴는 9개에서 4개 정도로 줄인다.
- 화면 위에 **'오늘 할 일' 3~4개**가 늘 보이게 한다. 무엇을 할지 헤매지 않게 하는 장치다.
- 시작할 때 **성별(남·여)·머리 모양·피부색**을 고른다. 입힌 옷이 3D 캐릭터에 그대로 보인다.
- 옷의 의미:
  - 촬영 때 입은 옷이 영상 분위기에 조금 영향을 준다.
  - 계절·날씨에 맞게 입으면 기분이 오른다.
  - 옷·신발은 돈을 쓰는 곳이다.
- 돈의 흐름: 유튜브(AI·직원 포함)로 벌고, 옷·신발·식재료·외식·가구·월세에 쓴다.
- 지금까지 만든 생활 막대(배부름·청결·기분), 소재 카드, 손맛 게임 3종은 버리지 않고 새 틀 안으로 옮긴다.
- 이전부터 유지하는 결정:
  - 그래픽은 Three.js 로우폴리 3D를 비스듬히 내려다보는 시점이다 (2D 픽셀은 사용자가 거절).
  - 현금 결제는 실물 성격 아이템만, 게임머니로도 살 수 있는 것만 판다.
  - 음악은 코드로 합성하는 작곡기를 쓴다 (업로드는 법적 위험).
  - 특정 기존 게임을 베끼지 않고 장르만 따른다.

## 4. 막힌 지점 / 미해결
- 하루 5분으로 바꾸면 경제 수치를 거의 전부 다시 맞춰야 한다 (`engine.js` CONFIG, 월세 30일 주기, 생활 감소 속도, 제작 시간 96시간 등).
- 1단계는 화면 구조를 거의 새로 짜는 일이다. `index.html`이 크니(약 900줄) 화면 부분을 나누는 것을 검토한다.
- 3D 캐릭터는 지금 남자 한 모델이다. 성별·옷을 바꿀 수 있게 하려면 `scene3d.js`의 사람 모델을 부위별(머리·상의·하의·신발)로 만들어야 한다.
- 풀세트 등 결제 상품 배율은 품질 보너스가 바이럴 기준(품질 70·80)을 넘기면 폭주한다. 새 밸런스에서도 무료 대비 3~4배를 지킨다.
- 공유 저장소(db)와 휴대폰 성능은 실기기에서만 확인할 수 있다.

## 5. 버린 접근법
- 하루 10초짜리 빠른 타이쿤 시간 → 생활 행동에 의미가 없어서 바꾼다.
- 기능마다 아래 메뉴 탭과 올라오는 창을 하나씩 더하기 → 산만하다는 피드백을 받았다. 방 물건과 오늘 할 일 중심으로 바꾼다.
- 소재 카드 품질 보너스 +2~4 → 풀세트가 폭주했다. 조회수 배율 위주로, 채널이 클수록 효과가 줄게 바꿨다.
- 2D 픽셀 그래픽, 방이 화면 1/3만 차지하는 배치 → 사용자가 거절했다.
- 조회수 식 `S^0.8`, 장르 계수 차이를 크게 두기, 후반 무제한 생산 → 폭주했다 (README 참고).

## 6. 참고
- 파일:
  - `engine.js`: 규칙과 수치. 생활은 LIFE, 동네는 PLACES 부분.
  - `index.html`: 화면.
  - `scene3d.js`: 3D 방·캐릭터·부엌.
  - `minigame.js`: 손맛 게임.
  - `decor.js`, `homeui.js`: 꾸미기.
  - `music.js`: 작곡기.
  - `community.js`: 공유 저장소.
  - `sim/simulate.js`: 밸런스 봇.
  - `build.js`: 한 파일로 합치는 빌드.
  - `docs/design-v0.3-life.md`: 1·2차 생활 설계.
- 확인 방법:
  - 밸런스: `node tycoon/sim/simulate.js 12`
  - 3D 화면 테스트: Playwright 크로미움을 `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader` 인자로 실행한다.
  - 저장 버전은 v3이다. 새 틀에서는 `migrate`로 올린다.
- 사용량 절약 (사용자가 사용량 급증을 걱정함):
  - 단계마다 새 대화를 연다.
  - 화면 사진 확인은 꼭 필요할 때만 한다.
  - 시뮬레이션은 짧게 돌린다.
  - 게임 플레이 자체는 Claude 사용량을 쓰지 않는다.
- 사용자는 PC의 claude.ai/code(또는 데스크톱 앱 Code)에서 이어 할 예정이다. 휴대폰의 게임 저장은 PC로 넘어가지 않는다(브라우저별 저장).
- 사용자 선호:
  - 한국어로, 영어·전문 용어를 피한다.
  - 부드럽고 친절한 존댓말을 쓴다.
  - 판단을 먼저 말하고 근거는 뒤에 붙인다. 완충어를 쓰지 않는다.
  - 선택지를 나열하지 말고 하나를 추천한다. 계획의 결함은 묻지 않아도 먼저 말한다.
  - 거짓말하지 않는다.
  - 설계 대화가 구현으로 흐르면 짚어 준다.
  - 커밋과 결과물에 모델명을 쓰지 않는다.
